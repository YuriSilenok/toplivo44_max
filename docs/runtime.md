# Общая реализация трёх MAX-ботов

Актуально на 26.11.2026. `app.py` обслуживает одно приложение, выбранное через `BOT_KIND`: `fuel`, `wifi` или `labor`. Каждое запускается отдельным процессом с собственной SQLite-БД. Python 3.12 используется на текущем VDS; зависимости закреплены в `requirements.txt`.

## Файлы

- `app.py` — модели Peewee, webhook, роли, диалоги, обработка событий и очередь доставки MAX.
- `portal.py` — импорт топлива, мониторинг источника, состояние ошибок и сводки устаревших данных.
- `datalens.py` — получение и разбор карты, безопасные детали ошибок.
- `manage.py` — серверное управление ролями, импорт и состояние БД.
- `register.py` — регистрация webhook трёх ботов в MAX; изменяет подписки, не является проверкой состояния.

Пользовательские сценарии: [топливо](https://github.com/YuriSilenok/toplivo44_max#readme), [Wi-Fi](https://github.com/YuriSilenok/free_wifi_max#readme), [трудовые права](https://github.com/YuriSilenok/tkrf_max#readme).

## Конфигурация

| Переменная | Назначение |
|---|---|
| `BOT_KIND` | `fuel`, `wifi` или `labor` |
| `BOT_USERNAME` | Имя бота для ссылок-приглашений |
| `MAX_BOT_TOKEN` | Секретный токен MAX |
| `WEBHOOK_SECRET` | Секрет проверки заголовка `X-Max-Bot-Api-Secret` |
| `DATA_DIR` | Каталог `bot.sqlite3`, по умолчанию текущий каталог |
| `PORT` | Локальный порт HTTP-сервера |
| `ADMIN_IDS` | Необязательные MAX ID начальных администраторов через запятую |
| `CA_BUNDLE` | Необязательный путь к доверенному набору CA |
| `MAX_API_URL` | По умолчанию `https://platform-api2.max.ru` |
| `FUEL_FEED_URL` | Необязательный альтернативный JSON-источник топлива; без него используется DataLens |
| `TZ` | На VDS `Europe/Moscow`, требуется для локального времени карточек топлива |

Установка зависимостей: `python -m pip install -r requirements.txt`. После загрузки переменных окружения запуск: `python -B app.py`. Приложение слушает только `127.0.0.1`, POST `/webhook`; снаружи требуется HTTPS reverse proxy и зарегистрированная подписка MAX. Не публикуйте токены в командах, README или Git.

Поддерживаются `bot_started`, `message_created`, `message_callback`; сообщения групп не обрабатываются как личные обращения. Входящие события дедуплицируются. Очереди и состояния диалогов сохраняются в БД; состояния действуют 10 минут. Доставка повторяется при временных сбоях; ответы MAX 403/404 удаляют соответствующее исходящее сообщение из очереди.

## Текущее размещение

| Приложение | systemd | Локальный порт | EnvironmentFile | База |
|---|---|---|---|---|
| fuel | `max-bot-fuel` | 8460 | `/etc/max-bots/fuel.env` | `/var/lib/max-bots/fuel/bot.sqlite3` |
| wifi | `max-bot-wifi` | 8461 | `/etc/max-bots/wifi.env` | `/var/lib/max-bots/wifi/bot.sqlite3` |
| labor | `max-bot-labor` | 8462 | `/etc/max-bots/labor.env` | `/var/lib/max-bots/labor/bot.sqlite3` |

Код: `/opt/max-bots/releases/`, ссылка `/opt/max-bots/current`, окружение `/opt/max-bots/venv`. Службы работают от `maxbots`; nginx направляет `/max-bots/<kind>/webhook` на локальный `/webhook`. Сейчас боты размещены на VDS владельца; перенос в инфраструктуру университета ожидает выделения ресурсов.

В каталоге `deploy/` репозитория `deploy.sh` описывает первоначальное размещение на существующем VDS. Скрипт привязан к его Python, CA и nginx, перезаписывает конфигурацию и регистрирует подписки: это не универсальный установщик и не команда проверки. `update-fuel.sh` и `update-labor.sh` создают резервные копии соответствующих БД и перезапускают соответствующую службу. Ссылка `current` общая: перед обновлением учитывайте совместимость всех приложений. Существующие службы ГИБДД, Pond и student-rescue сохраняются.

## Обслуживание без пробных обращений

```sh
systemctl status max-bot-fuel max-bot-wifi max-bot-labor --no-pager
journalctl -u max-bot-fuel -n 50 --no-pager
/opt/max-bots/venv/bin/python /opt/max-bots/current/manage.py fuel status
```

`manage.py` сам читает `/etc/max-bots/<kind>.env`, поэтому нужен доступ к выбранному конфигурационному файлу. `status` показывает число точек, администраторов и очереди. Импорт `app` также инициализирует схему и назначения из `ADMIN_IDS`; это не инструмент полностью неизменяющего чтения БД.

Доступные действия: `status`, `grant-admin --user-id <MAX_ID>`, `invite --minutes 30`, `import-wifi --file <JSON>`, `import-fuel --file <JSON>`. Назначение администратора ставит уведомление в исходящую очередь, для labor также передаёт ожидающие материалы; это реальное изменение, а не проверка. CLI `invite` создаёт приглашение администратора с заданным сроком (по умолчанию 30 минут), независимо от сроков приглашений в пользовательском меню.

Перед изменениями данных делайте согласованную резервную копию SQLite через backup API, а не простое копирование работающего файла с WAL. Секреты локального доступа находятся в защищённом хранилище родительского проекта; их содержимое не включается в документацию. По указанию владельца тесты и пробные обращения не запускаются.

## Альтернативный источник топлива

`FUEL_FEED_URL` возвращает массив записей либо объект `{"stations": [...]}`. Та же запись принимается `manage.py fuel import-fuel` в массиве:

```json
[{"id":"station-001","name":"АЗС","address":"Адрес",
  "latitude":57.77,"longitude":40.93,"updated_at":"2026-11-26T10:00:00+03:00",
  "fuels":{"АИ-92":{"available":true,"queue_minutes":0,"price":60}},
  "queue_text":"Нет","restrictions":"АИ-92: Нет"}]
```

`updated_at` — обязательная дата источника: ISO 8601 (без часового пояса трактуется как МСК) или Unix timestamp в секундах. `available` — JSON boolean. Не подменяйте дату источника временем импорта. Поддерживаются только АИ-92, АИ-95, ДТ. Описание повторов и уведомлений — в README топливного бота.

## Запуск из этого репозитория

Установите зависимости из requirements.txt, скопируйте .env.example в защищённый файл и заполните реальные значения. Загрузите их в окружение процесса и выполните python -B src/app.py из корня репозитория. Файл .env автоматически не читается. Данные по умолчанию в примере сохраняются в data/. Для отображения времени МСК используйте TZ=Europe/Moscow.

Исходники находятся в src/. В релизный архив для существующих скриптов кладутся файлы src/ без самого каталога и корневой requirements.txt. Из корня репозитория: tar -czf source.tar.gz -C src . -C .. requirements.txt. Для update-fuel.sh имя архива fuel-update.tar.gz; для update-labor.sh — labor-update.tar.gz. Скрипты на VDS ожидают архив в /opt/max-bots/. Саму публикацию в GitHub не следует считать развёртыванием на сервере.
