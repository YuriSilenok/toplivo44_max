# Функциональные требования к топливному MAX-боту для Костромского региона

**Стек:** Python, peewee, SQLite3.  
**Основной источник информации:** https://toplivo.kostroma.gov.ru/

## 1. Роли и их назначение

- **Гость** — любой пользователь бота, который ищет топливо. Это сценарий «водителя», отдельная роль в БД для него не требуется. Доступна только функция поиска топлива.
- **Оператор** — обновляет сведения о наличии топлива и очереди на своей АЗС.
- **Администратор** — управляет АЗС и ролями пользователей, а также имеет доступ к функциям оператора и поиску топлива.

Пользователь, перешедший по ссылке-приглашению, не получает отдельную роль «приглашённый». Он сразу получает выбранную роль: «Оператор» или «Администратор».

---

## 2. Общие функциональные требования

### ФТ-01. Запуск бота и определение меню

1. При запуске бота пользователь получает приветствие.
2. Бот определяет роль пользователя по данным в SQLite3 через peewee.
3. В зависимости от роли формируется меню:
   - **Гость:** только кнопка «Найти топливо».
   - **Оператор:** кнопки «Найти топливо» и «Обновить сведения».
   - **Администратор:** кнопки «Найти топливо», «Обновить сведения», «Добавить АЗС», «Добавить роль», «Удалить роль».
4. Недоступные для роли кнопки не отображаются.
5. При ручном вызове недоступного действия бот отвечает отказом:
   - для гостя при вызове «Обновить сведения»:  
     «Это действие доступно только оператору.»  
     Данные оператора не открываются;
   - для оператора при вызове «Добавить АЗС»:  
     «Это действие доступно только администратору.»  
     Форма добавления АЗС не открывается.

---

## 3. Сценарий поиска топлива

**Доступ:** любой пользователь, включая гостя, оператора и администратора.

### ФТ-02. Запуск поиска

1. Пользователь нажимает «Найти топливо».
2. Бот предлагает:
   - отправить координаты кнопкой «Отправить мои координаты»;
   - выбрать марку топлива кнопками: «АИ-92», «АИ-95», «ДТ», «АИ-98».
3. Все кнопки марок initially находятся в нейтральном цвете.

### ФТ-03. Передача координат

1. Пользователь нажимает «Отправить мои координаты».
2. Бот принимает координаты.
3. Бот просит выбрать марку топлива.
4. Кнопки марок остаются в нейтральном цвете.

### ФТ-04. Выбор марки и поиск

1. Пользователь нажимает одну из марок, например «АИ-95».
2. Кнопка выбранной марки меняет цвет на зелёный.
3. Бот выполняет поиск подходящих АЗС.

### ФТ-05. Выдача результатов поиска

Возможны следующие варианты ответа.

1. **Есть свежие подтверждённые данные и АЗС с координатами.**  
   Бот показывает до трёх ближайших АЗС.  
   Для каждой АЗС указываются:
   - адрес;
   - очередь в минутах;
   - время передачи информации;
   - ссылка «Открыть на карте».

   Пример ответа:  
   «Нашёл подходящие АЗС для марки АИ-95:  
   1. г. Кострома, ул. Советская, д. 1  
   Очередь: 10 минут  
   Информация передана: 14:05  
   Открыть на карте: https://yandex.ru/maps/?pt=40.926,57.767&z=17&l=map»

   В ответе не должны отдельно выводиться широта и долгота.

2. **Подходящих АЗС больше трёх.**  
   Бот показывает только три ближайшие АЗС.  
   Более далёкие АЗС в ответ не попадают.

3. **Нет свежих подтверждённых данных ни от оператора, ни с портала.**  
   Бот отвечает нейтрально:  
   «Сейчас нет актуальной информации о наличии этого топлива. Попробуйте уточнить позже.»

4. **Все операторы по этой марке отметили «Нет».**  
   Бот не показывает такие АЗС.  
   Если других АЗС с этой маркой нет, бот отвечает тем же нейтральным сообщением.  
   Запрещены формулировки «топлива нет», «отсутствует», пустой список, ошибка.

5. **Портал недоступен, но есть последние сохранённые свежие данные.**  
   Бот показывает подходящие АЗС по этим сохранённым данным.

### ФТ-06. Попытка вручную вызвать «Обновить сведения»

Если пользователь без роли оператора или администратора пытается вручную вызвать «Обновить сведения», бот отвечает:  
«Это действие доступно только оператору.»  
Данные оператора не открываются.

---

## 4. Сценарий обновления сведений оператором

**Доступ:** оператор и администратор. Администратор работает по тем же правилам.

### ФТ-07. Запуск обновления

1. Пользователь с ролью оператора или администратора нажимает «Обновить сведения».
2. Бот начинает последовательный опрос марок топлива его АЗС.
3. Бот показывает первую марку, например «АИ-92», и две кнопки:
   - «Есть» — зелёного цвета;
   - «Нет» — красного цвета.

### ФТ-08. Обработка ответа «Есть»

1. Пользователь нажимает «Есть» для текущей марки.
2. Кнопка «Есть» становится зелёной и активной.
3. Бот предлагает выбрать очередь кнопками: «0», «5», «10», «15», «20», «Более 30».
4. Все кнопки очереди находятся в нейтральном цвете.
5. Пользователь выбирает очередь, например «10».
6. Кнопка «10» становится зелёной.
7. Бот сохраняет сведения и отвечает:  
   «Сведения сохранены: АИ-92 — есть, очередь 10 минут, время передачи 14:05.»
8. Бот автоматически переходит к следующей марке, например «АИ-95», и снова показывает кнопки «Есть» и «Нет».

### ФТ-09. Обработка ответа «Нет»

1. Пользователь нажимает «Нет» для текущей марки.
2. Кнопка «Нет» становится красной и активной.
3. Бот сохраняет сведения и отвечает:  
   «Сведения сохранены: АИ-95 — нет. АЗС не будет показываться водителям по этой марке.»
4. Бот переходит к следующей марке.

### ФТ-10. Завершение опроса

После обработки последней марки бот отвечает:  
«Все марки обработаны. Спасибо.»

### ФТ-11. Напоминание об обновлении

1. Если оператор не обновлял сведения в текущем часу, в 55 минут текущего часа бот отправляет напоминание:  
   «Пожалуйста, обновите сведения о топливе на вашей АЗС.»
2. В напоминании есть кнопка «Обновить сведения».
3. Если оператор уже обновлял сведения в текущем часу, бот не отправляет напоминание.
4. Если напоминание не отправляется, кнопка «Обновить сведения» в нём не появляется.

### ФТ-12. Попытка оператора вызвать «Добавить АЗС»

Если оператор пытается вручную вызвать «Добавить АЗС», бот отвечает:  
«Это действие доступно только администратору.»  
Форма добавления АЗС не открывается.

---

## 5. Сценарий добавления АЗС администратором

**Доступ:** только администратор.

### ФТ-13. Добавление АЗС

1. Администратор нажимает «Добавить АЗС».
2. Бот спрашивает адрес АЗС.
3. Администратор указывает адрес.
4. Бот спрашивает координаты АЗС.
5. Администратор указывает координаты, например широта 57.767, долгота 40.926.
6. Бот предлагает выбрать марки топлива кнопками: «АИ-92», «АИ-95», «ДТ», «АИ-98».
7. Все кнопки марок находятся в нейтральном цвете.
8. В конце отображается кнопка «Готово».

### ФТ-14. Выбор марок топлива

1. При нажатии на марку, например «АИ-95», кнопка меняет цвет на зелёный.
2. При повторном нажатии на ту же марку кнопка возвращается в нейтральный цвет — выбор снимается.
3. Выбранные марки становятся зелёными.
4. Невыбранные марки остаются нейтральными.

### ФТ-15. Создание АЗС

1. Администратор нажимает «Готово».
2. Бот создаёт АЗС и отвечает:  
   «АЗС создана: адрес — <адрес>; координаты — 57.767, 40.926; марки — АИ-95, ДТ.»
3. Без координат АЗС не создаётся.
4. Бот всегда запрашивает координаты.
5. Пока координаты не указаны, переход к выбору марок и созданию АЗС невозможен.

---

## 6. Сценарий управления ролями администратором

### ФТ-16. Добавление роли

1. Администратор нажимает «Добавить роль».
2. Бот предлагает выбрать «Администратор» или «Оператор».
3. Администратор выбирает роль, например «Оператор».
4. Бот создаёт одноразовую ссылку-приглашение и отвечает:  
   «Ссылка-приглашение создана: <ссылка>. Действует 24 часа, срабатывает 1 раз.»

### ФТ-17. Удаление роли

1. Администратор нажимает «Удалить роль».
2. Бот показывает список пользователей.
3. Администратор выбирает пользователя.
4. Бот просит подтверждение кнопками «Да, снять» и «Отмена».
5. При нажатии «Да, снять» бот снимает роль и отвечает:  
   «Роль снята. Пользователь больше не видит кнопку <название кнопки>.»
6. При нажатии «Отмена» бот отвечает:  
   «Удаление отменено. Роль сохранена.»  
   Меню пользователя не меняется.
7. Если администратор выбирает самого себя для удаления роли и он единственный администратор, бот отвечает:  
   «Нельзя снять роль с себя, если вы единственный администратор.»  
   Роль администратора сохраняется.

---

## 7. Получение роли по ссылке-приглашению

### ФТ-18. Действующая ссылка

1. Пользователь переходит по действующей одноразовой ссылке.
2. Бот выдаёт роль, например «Оператор», и отвечает:  
   «Вы получили роль «Оператор». В меню доступны «Найти топливо» и «Обновить сведения».»

### ФТ-19. Просроченная ссылка

1. Пользователь переходит по ссылке, созданной более 24 часов назад.
2. Бот отвечает:  
   «Ссылка-приглашение просрочена. Попросите администратора создать новую.»
3. Роль не выдаётся.

### ФТ-20. Использованная ссылка

1. Пользователь переходит по ссылке, которая уже была использована.
2. Бот отвечает:  
   «Эта ссылка уже использована. Попросите администратора создать новую.»
3. Роль не выдаётся.

---

## 8. Требования к данным и реализации

### ФТ-21. Хранение данных

Использовать Python, peewee, SQLite3.  
Рекомендуемые сущности:
- `users` — пользователи бота;
- `roles` — справочник ролей;
- `user_roles` — назначенные роли;
- `stations` — АЗС, адрес, координаты;
- `fuel_types` — марки топлива;
- `station_fuel_types` — доступные марки на АЗС;
- `fuel_reports` — сведения о наличии топлива, очереди и времени передачи;
- `invite_links` — одноразовые ссылки, срок действия, факт использования.

### ФТ-22. Свежесть данных

1. Свежими считать сведения, переданные оператором или порталом в текущем часе.
2. Если портал недоступен, допускается использовать последние сохранённые свежие данные.
3. При отсутствии свежих подтверждённых данных бот отвечает нейтральным сообщением, указанным в ФТ-05.

### ФТ-23. Ссылки-приглашения

1. Ссылка действует 24 часа.
2. Срабатывает 1 раз.
3. При переходе проверяются срок действия и факт использования.
4. После успешного перехода пользователю назначается выбранная роль.

### ФТ-24. Проверка прав

1. Перед выполнением действия бот проверяет роль пользователя по данным в SQLite3 через peewee.
2. Недоступные действия не отображаются в меню.
3. При ручном вызове недоступного действия бот возвращает отказ, указанный в ФТ-01, ФТ-06 и ФТ-12.
4. Все изменения ролей, АЗС и сведений о топливе выполняются в транзакциях.

### ФТ-25. Получение сведений с портала

1. Получение сведений о топливе с портала https://toplivo.kostroma.gov.ru/ должно выполняться автоматически в 05 минут каждого часа.
2. Полученные с портала сведения сохраняются в SQLite3 через peewee и учитываются при поиске топлива наравне с данными операторов, если являются свежими в соответствии с ФТ-22.
3. Если в 05 минут каждого часа портал недоступен, используются последние сохранённые свежие данные в соответствии с ФТ-22.
4. Автоматическое получение сведений с портала не отменяет отправку напоминаний операторам по ФТ-11.
